# LLM 하네스 설계 (3차 STEP 03-3 재료)

## 한 줄 요약

LLM은 **읽고 쓰는 일만** 한다. 투자설명서에서 조건이 적힌 문장을 **번호로 가리키고**, 리포트의 요약과 이유 문장을 쓴다. **판정과 추론은 파이썬 규칙**이 한다. LLM 출력은 다섯 겹의 검사를 통과해야 채택한다.

현재 버전은 **v2.1 (2026-10-18)**, 기본 모델은 **phi4:14b**. 1차 실제 실행(v1)에서 드러난 문제를 v2에서 고쳤고, v2 실제 실행 뒤 근거 번호 정리·표현 검사·재채점을 더했다 (맨 아래 "최종 모델 선택과 v2.1"). 고친 이유와 v1 결과는 아래 "v1 → v2 개선"과 "1차 실제 실행 (v1)" 절.

## 흐름

```
투자설명서 원문 (SEC EDGAR 웹 스크래핑, 41만 자)
   │  ① 항목별 검색 — 8개 항목마다 근거 문장을 먼저 확보 → 문장 56개, 약 12,000자
   │     문장마다 [S번호]를 붙인다
   ▼
프롬프트 1: 조건 추출 (JSON 스키마 강제)  × N회 반복
   │  LLM은 값과 근거 문장 '번호'만 낸다 (문장을 베끼지 않는다)
   │  ② 스키마 검사 — 구조가 틀리면 재시도 (최대 3회)
   │  ③ 근거 검사 — 없는 번호이거나, 값의 핵심 단어가 가리킨 문장에 없으면 그 값을 버림
   │  ④ 다수결 — 표기를 정리한 값끼리 묶어 N회 중 같은 값의 비율을 '일치율'로 기록
   ▼
추출 사실 + 온체인 지표 ──▶ 파이썬 규칙 판정·추론 (일치 / 검토 필요 / 확인 불가)
   ▼
리포트 뼈대는 코드가 만든다 (판정별 절, 인용문, 수치, 데이터 범위)
   │  프롬프트 2: 요약과 '검토가 필요한 이유' 문장만 LLM이 쓴다
   │  ⑤ 숫자 검사 — LLM 문장에 입력에 없던 숫자가 있으면 표시
   ▼
reports/{fund}_report.md  +  대시보드 '문서 대 온체인' 탭
```

모든 프롬프트, 번호 붙은 발췌 문장(`sentences.json`), 원응답, 결과는 `llm/runs/날짜_펀드_단계/`에 남는다.

## 프롬프트

| 파일 | 역할 | 구조 |
|---|---|---|
| `prompts/01_extract_terms.md` | 번호 붙은 발췌문 → 8개 항목 (값 + 근거 문장 번호) | 역할 → 작업 → 항목 → 규칙 → 예시 → 출력 형식 |
| `prompts/02_write_report.md` | 판정 결과 → 요약과 '검토가 필요한 이유' | 역할 → 작업 → 규칙 → 입력 |
| `schema/terms.schema.json` | 추출 출력 형식 | 항목마다 `value`와 `evidence_ids` |
| `schema/report.schema.json` | 리포트 문장 출력 형식 | `summary`, `reasons[{item, reason}]` |

**가장 중요한 한 줄 (프롬프트 1의 규칙 1, v2):**
> For every non-null value, list in "evidence_ids" the [S] numbers of the sentences that state it.

v1은 근거 문장을 글자 그대로 베끼게 했다. 실제 실행에서 모델이 "(NAV)"를 빠뜨리거나 두 문장을 섞어, 맞는 값이 인용 검사에서 버려졌다. v2는 문장에 번호를 붙여 번호로 가리키게 한다. 그래서 인용 복사 실수가 원천적으로 생기지 않는다. 대신 "가리킨 문장이 그 값을 정말 말하는가"를 코드가 확인한다.

## 왜 이렇게 설계했나

| 결정 | 이유 |
|---|---|
| 판정·추론은 코드가 | 같은 입력이면 항상 같은 판정이 나와야 한다. 두 문장을 이어야 하는 추론은 14B·32B 모델 모두 하지 않았다 (v1 실측) |
| 근거는 문장 번호로 | 베끼게 하면 한두 글자 차이로 맞는 값이 버려진다 (v1에서 인용 거부 5/35). 번호는 틀릴 수 없고, 없는 번호는 바로 걸린다 |
| 근거-값 일치 검사 | 근거 문장이 원문에 있다는 것만으로는 부족하다. v1에서 "매일 재투자"에 '매일'이 없는 문장을 붙여도 통과했다 |
| 다수결 + 표기 정리 | 한 번의 출력은 우연일 수 있다. "a" 유무 같은 표기 차이는 같은 값으로 센다 |
| 항목별 검색 | 전체 점수 순으로만 뽑았더니 '주말 휴장' 문장이 발췌에서 빠졌다 (실제 발생) |
| 리포트 뼈대는 코드가 | v1에서 3개 모델 모두 '확인 불가'를 '검토 필요' 절에 넣고, 업그레이드 날짜를 데이터 기간으로 썼다 |
| 리포트 숫자 검사 | LLM은 그럴듯한 숫자를 만들어 낸다. 입력에 없던 숫자는 표시한다 |
| '위반' 대신 '검토 필요' | 시스템은 판단을 대신하지 않고 사람이 볼 지점을 짚는다 |

### 핵심 판정은 코드가 잇는다 — 배당 선언일 (주말·휴일 포함 여부)

LLM에게는 문장에 적힌 사실 세 가지만 찾게 한다. 그 사실을 잇는 추론은 코드가 한다.

| 사실 | 항목 | 원문 (BENJI 투자설명서) |
|---|---|---|
| 배당은 NAV 계산일에 선언 | dividend_declaration_timing | "...declare income dividends ... each day when it makes its final net asset value (NAV) calculation." |
| NAV는 NYSE·FRBNY가 여는 날에만 계산 | nav_calculation_days | "The Fund is open for business and calculates its NAV every day on which both the New York Stock Exchange (NYSE) and the Federal Reserve Bank of New York (FRBNY) are open for business." |
| 주말 휴장 | fund_closed_days | "Both the NYSE and FRBNY are also closed on weekends..." |

규칙: 세 사실이 모두 확인되면 문서상 주말 선언은 없어야 한다. 온체인에서 주말 지급이 0보다 크면 **검토 필요**다. 사실 하나라도 못 찾으면 '판정 보류 (문서 근거 부족)'로 남기고 지어내지 않는다.

## 하네스 자체 시험

### v2 (2026-10-18, LLM 없이 가짜 응답으로)

가짜 응답에 일부러 오류를 심고 하네스가 잡는지 확인했다.

| 심은 오류 | 결과 |
|---|---|
| 발췌에 없는 문장 번호 (S999) | 거부 (`rejected_unknown_id`) |
| 근거 문장에 없는 값 (보수 "0.35%") | 거부 (`rejected_value_not_in_evidence`) |
| 값은 맞지만 엉뚱한 문장을 근거로 ("daily" + 지급 형태 문장, v1 실제 실수 재현) | 거부 |
| 3회 중 1회만 다른 값 ("monthly") | 거부, 일치율 0.33 |
| 표기만 다른 같은 값 ("a proprietary…" / "proprietary…" / "A proprietary…") | 같은 값으로 묶임, 일치율 1.00 |
| 세 사실이 모두 있을 때 핵심 판정 | **배당 선언일 → 검토 필요** 자동 생성 |
| 리포트에 입력에 없는 숫자 (9,999,999) | 검출 |
| 리포트에 그럴듯하지만 입력과 다른 숫자 (27.3, 입력은 27.4) | 검출 |
| '검토 필요'가 아닌 항목에 이유를 씀 (보수) | 버려짐 |
| 리포트 데이터 기간 | 코드가 입력 그대로 기재 (2024-11-20 ~ 2026-10-06) |
| 핵심 문장 9개가 발췌에 포함되는가 | 9/9 |

**v1 실제 응답을 새 검사로 다시 채점:** v1에서 통과했던 qwen2.5:14b 응답 30건 중 4건(재투자 주기 "daily" + 무관한 문장)이 근거-값 일치 검사에 걸린다. phi4:14b·qwen2.5:32b는 새로 걸리는 것이 없다.

**알려진 한계:** 근거 문장 안에 숫자가 여럿이면 엉뚱한 숫자를 골라도 통과할 수 있다. 예를 들어 보수 표는 한 문장으로 잘리는데, 그 안에 관리보수 "0.15 %"와 총보수 "0.20 %"가 함께 있다. 보수는 온체인으로 확인할 수 없는 항목이라 판정에는 영향이 없다.

## 실행

```
python llm/harness.py all --fund BENJI --runs 5           # GPU 컴퓨터 (Ollama)
python llm/harness.py all --fund BENJI --runs 3 --dry-run # LLM 없이 하네스만 시험
```

`.env`: `OLLAMA_URL` (기본 `http://localhost:11434`), `OLLAMA_MODEL` (기본 `qwen2.5:14b`), `OLLAMA_NUM_CTX` (기본 16384 — Ollama 기본 문맥 약 4천 토큰으로는 발췌 1.2만 자 + 지시문이 넘쳐 앞부분 규칙이 잘린다)

GPU 컴퓨터에서 실행하는 순서와 정답표는 `../GPU_실행_인계.md`.

실행 PC: RTX 5070 Ti (VRAM 16GB) + 메모리 64GB. 14B급 4비트 모델(약 9GB)이 VRAM에 다 올라가고 문맥 여유도 남는다. 32B급은 VRAM을 넘어 느려지므로(v1 실측 약 15배) 모델 비교 실험에만 쓴다.

## GPU로 좋아지는 점

- **다수결 횟수 증가:** 무료·무제한 호출이라 N을 3에서 5~10으로 늘려도 비용이 없다
- **더 큰 모델:** VRAM이 클수록 큰 모델을 올려 추출 정확도를 높인다
- **더 긴 발췌:** 문맥 길이를 늘리면 발췌 한도 12,000자를 키워 근거 누락 위험이 줄어든다
- **문서가 밖으로 나가지 않음:** 외부 API에 투자설명서를 보내지 않는다
- **모델 비교 실험:** 같은 하네스로 모델 여러 개의 추출 일치율을 비교하면 발표 자료가 된다

## v1 → v2 개선 (2026-10-18)

1차 실제 실행(아래 절)에서 드러난 문제와 고친 방법.

| v1에서 드러난 문제 | 원인 | v2에서 고친 방법 |
|---|---|---|
| 핵심 판정 '배당 선언일 → 검토 필요'가 자동으로 안 나옴 | '주말 선언 여부'를 LLM이 두 문장을 이어 추론해야 했는데, 3개 모델 모두 5회 다 '언급 없음' | 추론 항목을 빼고 사실 항목(NAV 계산일)을 추가. 세 사실을 잇는 추론은 코드가 |
| 맞는 값이 인용 검사에서 버려짐 (qwen2.5:14b 5/35, phi4·32B는 보수 5회) | 근거 문장을 베끼다 "(NAV)" 누락, "0.20 %" → "0.20%" | 문장 번호로 가리키기 |
| 엉뚱한 근거가 통과 ("daily" + '매일'이 없는 문장, 4건) | 근거 문장이 원문에 있는지만 검사 | 근거-값 일치 검사 추가 |
| 리포트가 '확인 불가'를 '검토 필요' 절에 넣음 | 절 구성을 LLM이 결정 | 판정별 절은 코드가 만들고 LLM은 요약·이유만 |
| 리포트가 업그레이드 날짜를 데이터 기간으로 씀 | 입력 지표에 데이터 기간·체인이 없었음 (설계 실수) | 지표에 `chain`, `dividend_record_period` 추가, '데이터의 한계' 절은 코드가 작성 |
| 일치율이 표기 차이로 낮게 나옴 (공식 기록 0.60) | 값 문자열을 그대로 비교 | 대소문자·공백·앞 관사·끝 문장부호를 정리한 뒤 다수결 |

## 1차 실제 실행 (v1, 2026-10-18, GPU PC)

> v1 하네스·v1 프롬프트로 돌린 결과다. 여기서 드러난 문제를 v2에서 고쳤다 (위 "v1 → v2 개선"). 결과 파일은 v2 실행이 덮어쓰고, 원응답은 `llm/runs/20261018_10*`에 남아 있다.

|---|---|

| 메모리 | 64GB |

| 실행 | 추출 5회 | 리포트 | 전체 (`Measure-Command`) |

### 항목별 결과 (최종 실행)

| 항목 | 추출 값 | 일치율 | 상태 (5회) | 정답 대비 |
|---|---|---|---|---|

| declares_on_non_business_days | (없음) | 0.00 | 언급 없음 5 | ✗ 미추출 |
| dividend_payment_form | additional shares | 1.00 | 통과 5 | ○ |
| reinvestment_frequency | daily | 1.00 | 통과 5 | ○ 값은 맞음. 근거로 지급 형태 문장을 붙임 (그 문장에 daily 없음) |
| fund_closed_days | 공휴일 13개 목록 | 1.00 | 통과 5 | △ 공휴일만, 주말 누락 |
| share_price_target | stable $1.00 share price | 1.00 | 통과 5 | ○ |
| expense_ratio | 0.20% | 1.00 | 통과 5 | ○ |
| official_record | a proprietary blockchain-integrated system | 0.60 | 통과 5 | ○ (일치율이 낮은 건 "a" 유무 등 표기 차이) |

- **정답 8개 중 5개 맞음**, 1개 부분 정답(휴장일), 2개 실패(배당 선언 시점, 주말 선언 여부)
- **평균 일치율:** 8개 기준 0.70, 값이 나온 6개 기준 0.93

### 실패 원인 (원응답 `raw_*.json` 확인)

- **숫자 검사:** LLM 문장에 입력에 없는 숫자 없음 (세 모델 모두)

## v2.1 → v2.2 (2026-10-18, 원래 PC) — 리포트 표현 문제
