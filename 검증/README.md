## 3. 전처리 — 확정안과 구현 중 바뀐 점 (3차 STEP 02-2)

| # | 이슈 | 적용한 방안 |
|---|---|---|
| 1 | 배당과 청약 혼재 | 트랜잭션 → 행 단위 판별. 정의: "잔고가 있는 지갑 2개 이상에 잔고의 1% 미만씩 동시 발행". **펀드별 규칙**: BUIDL은 배당 전용 함수 `bulkIssuance`의 동시 지급 전체, BENJI는 "지급률 × 직전 지급 이후 최고 잔고 × 3"을 넘는 행을 청약으로 분리 |
| 2 | 배당 주기 변경 | 지급 간격 20일 이상이면 월배당기. 월 단위 재합산표 별도 |
| 3 | 요일·공휴일 효과 | 직전 지급일과의 경과일로 나눠 1일 지급률로 정규화. 같은 날 두 번째 지급은 제외 |
| 4 | 소각 혼재 | `Burn` 이벤트의 사유 문자열 우선, 없으면 함수 이름으로 상환 / 클래스 전환 / 체인 이동 분리 |
| 5 | 함수 미해석 | 공개 시그니처 DB로 9개 전부 해석 |
| 6 | 특수 지갑 | 배당 비례 이탈률 90% 이상, 지급 10회 이상이면 표시. 추가로 행 단위 **"잔고 기준 불일치"** 표시 |
| 7 | 단위·시간 | 금액은 토큰 단위. UTC 원본 + 미국 동부(분석 기준) + 한국 시간(표시용) |
| 8 | 범위 | Ethereum만 |

**구현하면서 새로 찾은 전처리 이슈 (STEP 02에 쓰기 좋은 실례)**
- **부동소수점 먼지 잔고:** 전액 상환한 지갑에 0.000000001 수준 잔고가 남아 보유자 수가 56개에서 64개로 부풀었다. → 토큰 0.000001개 이하는 0으로 처리
- **트랜잭션 단위 판별의 한계:** BENJI는 한 트랜잭션에 그날 배당과 대규모 청약을 묶어 실행한다. 트랜잭션 단위로 판별하자 배당이 9,535만 달러로 부풀었다(실제 328만 달러). → 행 단위로 판별
- **일할 계산 때문에 비율 기준이 실패:** 지급 직전에 상환한 지갑은 그 달 평균 잔고만큼 배당을 받아 직전 잔고 대비 1%를 넘는다. → "직전 지급 이후 최고 잔고" 기준으로 상한
- **펀드마다 기록 방식이 다름:** BUIDL은 용도별 함수가 따로 있고, BENJI는 모든 작업이 `signedDataExecution` 하나다. → 판별 규칙을 펀드별로 둔다
- **선지급 펀드에는 경과일 정규화가 안 맞음:** 업그레이드 전 BENJI는 금요일에 주말분을 미리 줬다. → 펀드 간 비교는 주 단위 합산이 안전

## 4. 발견 (3차 STEP 04 인사이트)

1. **배당 주기 변경 (BUIDL):** 2024-05 ~ 2025-01은 월 1회, 2025-01-23부터 영업일 매일. 공개 자료들은 "매월 지급"으로 설명한다 → 문서 대 실제 후보 (BUIDL은 사모라 공식 문서 미확보)
2. **정규화 효과 (BUIDL):** 연율 표준편차 20.25%p → 0.38%p. 지급률은 연 4.9%(2024)에서 3.2%(2026)로 내려가 미국 금리 인하와 같은 방향 (`fig_rate_normalized.png`)
3. **업그레이드 이력이 정반대:** BUIDL은 업그레이드 가능 구조인데 2년 반 동안 **0회** (규제 규칙은 별도 서비스 컨트랙트 12개로 분리). BENJI는 운영 중 **2회** (2025-05-23, 2026-02-12)
4. **BENJI 업그레이드 날 배당 방식이 바뀜:** 업그레이드 전 지급 126회의 주말 비율 **0%**, 2025-05-23 업그레이드 뒤 **27%**. 투자설명서(2026-08-01)는 "NAV를 계산할 때 매일 배당을 선언"한다고 쓴다 → 업그레이드 뒤 주말 발행이 이 문구와 맞는지가 핵심 대조 질문 (`fig_weekday.png`)
5. **소각의 23%는 상환이 아님 (BUIDL):** 20.6억 달러 중 상환 15.9억(76.9%), 클래스 전환 4.1억, 체인 이동 0.6억. 2025-07에 4억 달러가 다른 클래스에서 들어와 8월·10월에 다시 나갔다 (`fig_flows.png`)
6. **잔고로 설명되지 않는 배당 (BUIDL):** 배당 3,299만 달러 중 **27.9%(920만 달러)**가 받은 지갑의 온체인 잔고로 설명되지 않는다. 지갑 20개, 한 지갑이 707만 달러
7. **규제 기능은 있지만 한 번도 안 씀:** 강제 이전 `Seize` 0건, 거래 정지 `Pause` 0건
8. **보유 집중:** BUIDL 58개 지갑 중 상위 1개 27.0%, 상위 5개 70.5%. BENJI(Ethereum)는 3개 지갑
